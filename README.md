# Gate.io Pump → SHORT Radar

Незалежний вебвіджет для спостереження за ф'ючерсами Gate.io. Він розділяє три різні питання: чи є памп, чи з'являються ознаки його виснаження та чи є підтвердження для SHORT. Це аналітичний інструмент, а не торговий бот і не гарантія прибутку. «Відносно безпечний SHORT» не означає безпечну або прибуткову угоду.

## Запуск

Відкрийте `index.html` у браузері або опублікуйте файли в корені GitHub Pages. Для браузерів, які блокують `file://`-запити, запустіть локальний статичний HTTP-сервер. Збірка, фреймворк і ключі API не потрібні. Дані завантажуються безпосередньо з публічного API Gate.io; доступ залежить від мережі, DNS і CORS браузера.

Початковий список: `BTC_USDT`, `ETH_USDT`, `SOL_USDT`. Щоб додати контракт, введіть точний символ (наприклад, `RAVE_USDT`) і натисніть «Додати пару». Пара додається тільки якщо присутня серед активних контрактів USDT Gate.io. Кнопка ✕ видаляє пару. Список зберігається у `localStorage` цього браузера.

## Дані та обмеження API

Використовується офіційний [Gate API v4](https://www.gate.com/docs/developers/apiv4/en/) та згенерований Gate довідник його [REST endpoints](https://github.com/gate/gateapi-python/blob/master/docs/FuturesApi.md):

| Endpoint | Поля / використання |
| --- | --- |
| `GET /api/v4/futures/usdt/contracts` | Список контрактів `name`, `status`; контрактні `funding_interval` (секунди), `funding_rate`, `funding_next_apply` |
| `GET /api/v4/futures/usdt/tickers` | `contract`, `last`, `mark_price`, `index_price`, `funding_rate`, `volume_24h_quote` |
| `GET /api/v4/futures/usdt/candlesticks?contract=…&interval=…&limit=80` | Свічки `t`, `o`, `h`, `l`, `c`, `v`, `sum` з інтервалами `5m`, `15m`, `1h`, `4h` |
| `GET /api/v4/futures/usdt/contract_stats?contract=…&interval=5m&limit=60` | Історичні `time`, `open_interest`, `open_interest_usd`, `lsr_account`, `lsr_taker`, `long_liq_usd_new`/`short_liq_usd_new` (або задокументовані `long_liq_usd`/`short_liq_usd`) та інші статистики контракту |

У Gate API також задокументовані `GET /futures/usdt/funding_rate` з історичними `t`/`r` і `GET /futures/usdt/liq_orders` з `time`, `contract`, `size`, `order_size`, `order_price`, `fill_price`. Вони не потрібні для цього віджета: funding береться з ticker разом із контрактним інтервалом, а `liq_orders` не містить документованого поля напрямку ліквідації. У ticker також є 24h change/high/low; сигнал використовує власні закриті свічки, тому ці поля не використовуються у формулі.

Свічки беруться лише з минулими часовими мітками та відкидаються, доки інтервал свічки не завершився. Індикатори й переходи станів використовують закриті 15-хвилинні свічки, тому поточна незакрита свічка не може змінити історичний сигнал. Відсутні або некоректні значення не замінюються нулями.

Volume Ratio використовує `v` (обсяг у контрактах) із закритих 15m свічок і середній обсяг попередніх 20 свічок; ticker `volume_24h_quote` відображається окремо. OI береться з `contract_stats` (`open_interest` у контрактах і `open_interest_usd` у доларовому еквіваленті), а 15m/1h/4h зміни — з історичних статистичних записів. Long/short показується окремо за точно названими полями `lsr_account` (співвідношення рахунків) та `lsr_taker` (співвідношення taker-позицій); ці показники не є тотожними. Ліквідації LONG/SHORT беруться з USDT-специфічних `long_liq_usd_new`/`short_liq_usd_new`, якщо вони повернуті; інакше — з документованих `long_liq_usd`/`short_liq_usd` останнього 5m запису. Неповні поля позначаються як такі, а не доповнюються нулями.

Funding враховується лише коли API повертає ставку й достовірний `funding_interval` у секундах. Відомий період нормалізується до 8 годин; якщо період відсутній, Funding показується як UNKNOWN і не входить у score.

Long/short ratio та ліквідації доступні через `contract_stats`, але їхні визначення обмежені документованими полями; віджет не виводить з них загальну кількість LONG/SHORT-позицій. Публічні `liq_orders` містять події ліквідації, але не документують напрямок сторони, тому для розділення LONG/SHORT використовуються лише агрегати `contract_stats`. Числовий ліміт запитів і гарантію CORS не підтверджено; частота 60 секунд і три паралельні пари — обережні налаштування, а не твердження про ліміт API. API може тимчасово бути недоступний або не дозволити запити з браузера — у цьому разі дані не вважаються нульовими, а віджет показує попередження.

## Стани та оцінки

- **WATCH / PUMP** — аномальний рух ціни; для високого PUMP score потрібне одночасне підтвердження зростання ціни та обсягу.
- **OVERHEATED / EXHAUSTION** — перегрів, уповільнення momentum або інші незалежні ознаки виснаження. Самі по собі високий RSI чи funding SHORT не створюють.
- **SHORT SETUP** — памп і виснаження супроводжуються ранніми ознаками слабкості; це ще не підтвердження входу.
- **SHORT ENTRY** — закрита 15m свічка пробила локальну підтримку та є додаткове bearish-підтвердження. Оцінка моделі не є ймовірністю прибутку.
- **SHORT скасовано** — ціна закрилася вище рівня інвалідації попереднього SHORT-сценарію.

`PUMP`, `EXHAUSTION` і `SHORT` — окремі шкали 0–100, це прозорі евристичні бали, не статистично навчена модель. PUMP враховує зміни ціни на 5m/15m/1h/4h та співвідношення обсягу закритої 15m свічки до середнього попередніх свічок. EXHAUSTION враховує RSI, уповільнення momentum, MACD, верхню тінь, можливу дивергенцію OBV, падіння OI, крайній L/S account ratio та перевагу SHORT-ліквідацій. Funding є лише малим допоміжним фактором при відомому інтервалі. SHORT вимагає пампу, ознак виснаження, достатньої історії та якості даних, пробою підтримки й bearish-підтвердження. Відсутні дані знижують повноту оцінки, а не стають нульовими показниками.

У режимі очікування всі пари зі списку залишаються видимими, а картки впорядковуються за близькістю до підтвердженого SHORT і балами сценарію. Статус і пояснення показують спокійний ринок, формування пампу, перегрів/виснаження, очікування пробою або підтверджений SHORT; окремо відображається повідомлення, якщо активних SHORT немає. При помилці оновлення картка позначає дані недоступними, не перетворює оцінки на нулі та зберігає час останнього повністю успішного оновлення.

Індикатори обчислюються лише з історичних закритих свічок. RSI — 14 періодів; MACD — 12/26/9; ATR — 14. OBV-дивергенція позначається лише при новому локальному максимумі ціни без підтвердження максимуму OBV.

## Entry, Stop, цілі та ризик

Рівні наводяться лише для SHORT SETUP/ENTRY і є приблизними. Entry — закриття останньої 15m свічки. Stop — більший із локального максимуму останніх 20 свічок або Entry + 1 ATR, із додатковим буфером 0,2 ATR. TP1 — найближча локальна підтримка з 15m структури нижче входу; за її відсутності — 1 ATR. TP2/TP3 — 2/3 ATR. ATR відображає поточну волатильність; рівні не гарантують виконання. Risk/Reward рахується від Entry до Stop і TP1.

## Якість та оновлення

Для показників використовуються стани `OK`, `NO DATA`, `STALE`, `CONFLICT`, `INCOMPLETE`, `SUSPECT`. Віджет оновлюється приблизно раз на 60 секунд, обмежує одночасні пари трьома та кешує повторні запити. Сповіщення створюються лише при зміні стану; за дозволу браузера додатково показується системне сповіщення. Сигнали використовують тільки закриті 15m свічки; відкриті та майбутні свічки відкидаються.

## Додаткове підтвердження SHORT

RCI, OBV, EMA та KDJ працюють окремо від основного алгоритму. Вони не змінюють пошук пампу, бали, базовий SHORT SETUP/ENTRY, пороги або сортування. Панель показує базовий сигнал окремо від оцінки індикаторів; налаштування зберігаються в `localStorage`. Стандартні значення: RCI(9), OBV(10), EMA(9/21), KDJ(9). Їх можна налаштувати або вимкнути окремо; кнопка «Відновити стандартні» повертає початкові параметри. Якщо вимкнути всі чотири, додатковий модуль не додає підтвердження, і основний радар зберігає попередню поведінку.

Пояснення розрізняє перегрів без підтвердженого розвороту, виснаження, очікування підтвердження ціною, узгоджене підтвердження індикаторами та суперечливі сигнали. Перекупленість сама по собі не є умовою SHORT-входу. Для позначки індикаторного підтвердження потрібен чинний базовий SHORT ENTRY і достатня узгодженість доступних налаштованих індикаторів. Відсутня історія, пропущені обсяги або некоректні налаштування позначаються окремо; вони не підміняються нейтральними/нульовими значеннями й не змінюють базовий сигнал. Зміна параметра переобчислює цей індикатор і загальну оцінку, повторно використовуючи результати інших індикаторів для тієї ж закритої свічки.

Якість підтвердження — евристична оцінка, а не ймовірність прибутку; ризик сценарію залишається. Нові індикатори не пройшли історичну перевірку чи оптимізацію на відкладених даних.

## Тести

Потрібен Node.js із вбудованим test runner:

```sh
node --test
```

Тести перевіряють якість і нормалізацію даних, закриті свічки/no-lookahead, stats/funding, індикатори та сигнали, ізоляцію додаткового підтвердження, інвалідацію SHORT і керування списком пар. Результати моделі не є інвестиційною порадою; ф'ючерсна торгівля має високий ризик.
